# Paper Hygiene Audit — Checks, Lenses, Configuration, False Positives

Reference for [`SKILL.md`](../SKILL.md). The scanner's check table is the single source of truth — `python3 "$HYGIENE_SCANNER" list-checks --format md` prints every check with its layer, certainty, default and confirmed level, and route. This page explains what each family catches and how a user configures and exempts. Which findings `— fix` may change is the whitelist in SKILL.md Step 5; everything else goes to the fix plan.

## Check families

| Family | Catches | Built-in exemptions |
|---|---|---|
| XREF | `??`, `[?]`, `(?)`, printed cite keys in the PDF text; undefined references or citations, Rerun requests (natbib included), multiply defined labels in the log; missing entries in `.blg`; `\ref` / `\cite` keys with no label or entry in the sources (the note names the closest existing labels or keys and how many keys share the `\cite`; a `\ref` key lists every place it is referenced, `ref_places`, and its closest labels, `close_labels`, which the plan prints; `fix_target` when exactly one defined label of the same kind is close to the key — the repair changes every place — `fix_drop` for a dangling key inside a multi-key `\cite` with no similar key); BUILD-STALE (PDF older than what it is built from) | `???`; a `??` whose surrounding text is typeset verbatim in the sources is INFO — a `??` in reference context (`Table ??`, `(??)`) never is; stale PDF bookmarks only (`Rerun to get outlines right`) are WARN |
| LOG | TeX errors in a PDF built past them; overfull boxes (count and worst); missing glyphs and font shapes | — |
| ENG | Definite: library and toolchain versions (ENG-VER, English and Chinese phrasing), paths (ENG-PATH), private hosts, IPs, and share links (ENG-NET), commands and environment-variable prefixes such as `CUDA_VISIBLE_DEVICES` or `MKL_NUM_THREADS=` (ENG-OPS), commit ids and long hashes (ENG-HASH), secrets (ENG-SECRET, always redacted), deny-list terms (ENG-DENY). Candidates: framework names, accelerator/CPU models and counts, CPU-only runs, infrastructure phrasing, launch logs, code hashes, file names of the code or the supplement in the prose (ENG-FILENAME: `run_eval.py`, `configs/base.yaml`; a README is INFO, a pointer the reviewer still sees), precision and loading detail (ENG-PRECISION, only with policy `precision_disclosure: candidate`); a hardware word that names a measured quantity of the study (`measured CPU cost`, `peak GPU memory`, no amount before it), and a compute measure named with no amount next to it (`peak memory`, `fewer GPU-hours`; `120 GPU-hours` or `peak memory of 40 GB` stays a candidate), is WARN at most and never deleted automatically (`hw_usage`). | PROC | Definite: clock times with a time zone. Candidates: dates and launch stamps, seeds shaped like a date next to "seed" or "salt" (PROC-DATESEED), review and rebuttal talk (simulated reviewers included), revision talk (round-2, phase_3, re-ran, hotfix, earlier runs, "the user asked"), AI-tool authorship outside the AI-use statement, unfinished work (PROC-PENDING: "not yet evaluated", "to be added", "results pending", TBD — for a person, never reworded away), registration amendment and addendum labels (PROC-REGLABEL, only with policy `registration_labels: flag`). Recall candidates for a person (`plan_only`, never fixed automatically): a batch called by when it ran (previously trained, the earlier … sweeps, historical runs, added later), the story of how a registered design changed (were replaced by, was appended to, changes listed in the order they were made — reported under `registration_labels: keep` too, which keeps the labels, not the story), a run or a registration named by its date or its order (the registered submission date, the second registration) | references, Accessed/Retrieved and posted/published-after dates, the template's "Under review" header, `stage 2` / `phase 2`, preregistration amendment labels (with `registration_labels: keep`), "the original registration" (the registration itself, as against its amendments — never a round), data-handling disclosures, "[TBD]" (a TEXT-MARKER), "released upon acceptance" |
| ANON | identity terms (redacted `[ANON#n]`; in a PDF metadata field of the sources a WARN even when the PDF does not show it), e-mails, a non-anonymous `\author` or final-version switch, acknowledgments, owner-identifying links; candidate first-person self-citation; probable internal code names (ANON-CODENAME: a lower-case name the supplement's layout gives — its top folder, a top-level Python package folder (not a sub-package, not vendored code), a `/path/to/<name>` placeholder — that the paper's text uses is a WARN candidate; a title word, top folder, or `project=` value that recurs in the supplement but never in the PDF is INFO; a name an earlier round reported stays reported while any occurrence is left) | placeholder e-mails, anonymized hosting links, the references (INFO); a method named in capitals (`AdaRank`) is not its lower-case package name |
| META | PDF Info fields, non-UTC dates, `PTEX.*` keys with paths or identity terms, XMP creator, identity terms or paths in decompressed streams, embedded files; figure metadata (META-FIGURE): tool versions, an author, or a local time zone in a figure's XMP inside the PDF or in a PDF member of the supplement (WARN in anonymous mode), and in the figure files the sources include (INFO: they ship only with a source upload) | font-program dates; a plain relative figure name is INFO |
| TEXT | literal `\n`, visible control words, Markdown residue, TODO / `[VERIFY]` markers, U+FFFD, zero-width characters; an escape glued to words on both sides (`see\nTable`) is never verbatim, however the source spells it; candidates: snake_case, glued words (including `Eq. (3)gives`), hidden reviewer-directed instructions, math-glyph artifacts; WARN for a text layer without real spaces (pdfTeX without interword spaces, or words a second extractor reads glued) — no verified automatic fix, so for a person; Type 3 fonts (TEXT-T3FONT, INFO) | text typeset verbatim in the sources — listings, `\texttt`, table cells, an escape that stands apart in prose (INFO, still reviewed as a low-priority group); line-end hyphen compounds; large-delimiter private-use glyphs; listings line-break arrows |
| PAGE · TPL · ENDM | body past `— page-limit`; body not ending on and filling `— fill-page`; geometry, spacing, or font-size overrides; non-official style files (`— style-ref`); missing or out-of-order end-matter statements (`— end-matter`) | line-number columns, running headers and footers; a sentence that starts with "Appendix C describes …" is not a heading |
| SUPP | `.git/`, `__MACOSX/`, `.env`; ARIS and agent files (`.aris/`, `CLAUDE.md`, `AGENTS.md`, ARIS audit reports, fix plans, and state files, traces); run logs and runtime artifacts (`*.log`, `nohup.out`, `slurm-*.out`, `wandb/`, `mlruns/`, `lightning_logs/`, `events.out.tfevents.*`; candidates); identity terms, paths, secrets, user@host, an account at a host after ssh or scp with no path after it (`ssh ada@10.9.8.7`; a usage example such as `user@remote-host` is none), a login made from an author's name (first initial and last name, first and last name with or without a dot or an underscore) before an `@`, a host name where a note logs in or runs (`run on node12:`, `ssh … node12`; `gpu0` alone is a device index), or internal hostnames in member text (WARN inside data records) or names; clock times, dates (month and year included), and process talk (internal batch names, sealed or superseded plans, instructions about the manuscript, unfinished work and status strings such as `X_RESULTS_PENDING`) in READMEs, code comments, and docstrings; candidates in notes and shell or config files: environment-variable prefixes of a command (`CUDA_VISIBLE_DEVICES=0 python …`), short hashes after commit/sha/hash (also in data records), seeds shaped like a date, and — by policy — precision detail and registration labels; run timestamps in data records, code literals, and log lines; date stamps in records and code literals; timestamps inside identifiers; date, round (`_r2`, `r3b_`), version, and fix markers in names, and working-copy endings (`_now`, `_prev`, `_old`, `_new`, `_tmp`; candidates); process files (SUPP-PROCFILE: root cause, post-mortem, as-found, superseded, wip anywhere in a name; `_old` at the end of a file name; NOTES, TODO, STATUS, STOP, REVIEW, ROUND, HANDOFF, PROGRESS, or `_draft` at the end of a document's name; a process-like title — candidates; addendum, amendment-draft, and clarification files are registration records: INFO with `registration_labels: keep`, candidates with `flag`); placeholder roots and dangling references (SUPP-PATH: `<DATA_ROOT>/x` or `${ROOT}/x` in code and records, a script the package does not contain, an old name left after a rename; a code note's path into a folder the package lacks, and a relative path in a code literal that resolves to nothing in the package, are INFO); hardware, OS, and host words in notes and names (SUPP-HW: candidates whose confirmed level follows `hardware`, INFO with policy `supp_hardware: info`; the places where the word names a measured quantity or sits in a heading's brackets are a finding of their own, WARN at most and never drafted as a deletion; a finding whose every place is code — a code line, or a string the code uses such as a table template or a prompt, read by the member's language — is for a person, never a `supp-delete`); recall candidates for a person (`plan_only`, never edited): the authors' machine written into `os.environ` as a literal (a device list, a cache path, a tracking account; a value read from an argument or an offline switch is configuration), debug output, a working-copy module alias, a data record's note, verdict, comment, reason, or description field that tells the run's story; code that writes the run time into its outputs (SUPP-RUNTIME: INFO, WARN under `--strict`, for a person); documents in another script than the paper (SUPP-LANG, INFO); zip comments and real timestamps, gzip and tar owner, name, comment, and time fields (`repack` clears them, tar members included, and reports the archive's size and any member a re-compression made larger); a phrase a verified deletion removed from the paper but still in a supplementary note; corrupt, truncated, or oversized archives (`supp_max_mb`). Findings group by member kind (doc, code, data, log). Reviewer batches: every member must be marked checked, and notes the review text budget left out or cut short count as not covered (SUPP-COVERAGE); data records and code or logs without a note line are never in a batch (only the rules read them; `not_in_review` counts them) | dependency lists, versions, install commands, hashes, seeds in code, date ranges and dates assigned as data parameters (windows, cutoffs — unless one of the authors' own process verbs such as registered, written, or relaunched stands between the keyword and the date), registration record numbers — reproduction needs them; placeholder roots in a README command or a comment (usage notation, INFO); `${VAR}/x` in shell scripts and configs; hardware words in code lines; `max_new_tokens`-style names (a working-copy ending counts only at the end of a name) |
| NUM · CONFIG · ALLOW | numbers changed against the fix baseline, with the sentence they left or entered; CONFIG_DIR changed mid-loop (fix rounds only); allow-list lines that are malformed, too broad, non-exemptable, or unused | figure and section numbers, citation years; a number that only moved between the body and the references or checklist (a float placed after the references) is INFO; a number that left with the sentence of a confirmed leak (a definite finding, a candidate ruled leak or reword, a blocking reviewer finding) is INFO and never reviewed; an integer that left together with a deleted clause holding an unconfirmed round-0 finding is INFO and still goes to the reviewer |
| FIX | what the fix loop itself broke: FIX-REGRESSION against the previous round and against round 0 (new stray math-font glyphs such as `±←` beyond what the sources add, a new `??` or `(?)`, more glued words, a body that stops filling the required page or keeping the page limit — BLOCK; a page count that grew — WARN, or INFO while the body ends where it did and keeps its fill and limit (a float placed later); the edits of the round that caused it are undone — for a layout regression half of the suspects per rebuild, each retried once in the next round); FIX-EDIT (a change since round 0 that the whitelist refuses: words added or replaced, a deletion no fix-queue item asked for, a code line, data member, or member name changed, a reference moved to an unverified label — BLOCK, undone by its E-id, a member change put back from round 0's supplement; whether a member left the archive is judged by its complete name list, so one past the scan budget is not compared, never left out; `finalize --contest-edit` recomputes a contested one from the files and overturns it only when the bytes agree) | glyphs the sources themselves add (`\leftarrow`, `\gets`, `\psi`, `\textvisiblespace`) |

## Review lenses

| Lens | Default | Reads for | Norm (cited, not redefined) | Max level |
|---|---|---|---|---|
| `triage` | on | each candidate group: leak, reword (keep the fact, change the wording), necessary, false_positive, or uncertain | this skill | `leak`: the check's confirmed level (WARN when the review is same-family); `reword`: WARN — but revision or review narration whose sentence or clause says nothing else is a leak at the confirmed level |
| `engineering` | on | environment, infrastructure, and tooling detail; process and revision narration — in the PDF and in the supplementary texts (READMEs, code notes, log heads) | `/paper-write` Key Rules 5 and 8 | WARN (a `blocking` one is a confirmed leak) |
| `anonymity` | on in anonymous mode | identity, self-citation, acknowledgments, links | the venue's double-blind policy | WARN (a `blocking` one is a confirmed leak; BLOCK when its quote holds deterministic identity evidence — an identity term, a home path, an account at a host, a login made from an author's name, a host name where a note logs in or runs, a private IP, an internal host name) |
| `statements` | on when end matter is found | AI-use, ethics, and reproducibility statements: no engineering detail, pointers only, consistent with `declared_ai_uses` | `shared-references/venue-checklists.md`, `policy.json` | advisory; a confirmed contradiction (WARN) only with `declared_ai_uses` |

Every lens shares one guardrail: never recommend deleting a reported result — tables stay complete (`/paper-write` Key Rule 10) — and never change numbers, citations, formulas, or claim scope (Key Rule 7). Required disclosures (AI use, data handling, preregistration deviations) are never leaks. A rewrite keeps every ordering (a date that orders events becomes after/before), keeps every result, conclusion, decision, rule, commitment, and deviation the sentence states, keeps the subject and tense of a re-run that supports a claim, deletes an author's marker instead of rewording it, and adds nothing. A reviewer's own finding is never applied automatically: it goes to the fix plan.

One more fresh reviewer uses the same routing: a **batch reviewer** per supplementary batch reads every member against the checklist (engineering, process, dates, identity, unfinished, codenames) and lists the members it checked. Each batch file opens with the venue policy, and a reviewer finding that holds only what the policy keeps (a registration label or the order it states, precision, a hardware note with `supp_hardware: info`) is INFO with the ruling `necessary_by_policy`.

## User configuration

CONFIG_DIR is `.aris/paper-hygiene/` at the project root. Every file is optional and written by the user only — the executor never creates or edits it.

```
# .aris/paper-hygiene/anon-names.txt — one identity term per line
Alice Example
Example Lab
example-host-01
```

```
# .aris/paper-hygiene/allow.tsv — check_glob<TAB>regex<TAB>approved_by<TAB>reason[<TAB>where]
ENG-HW	\bA100\b	human:first-author	latency claim in Sec. 5 is measured on this accelerator
PROC-*	\bagents?\b	cross-family-review:thread-0000	the paper studies LLM agents
```

- `approved_by` is `human:<id>` or `cross-family-review:<thread-or-agent-id>`; a **definite** finding accepts only `human:`.
- The optional fifth column `where` scopes a line: `page=12` (or `page=12,13`), `file=sections/setup.tex[:42]`, or `member=code/*`.
- Lines are refused (ALLOW-INVALID, WARN) when they are malformed, lack typed provenance, use a `*` glob, have a regex that matches the empty string or holds fewer than three literal characters, target a build-log check (the log is the compiler's own statement — fix the build), or exempt a printed `??` / `[?]` without `where: page=N`.
- Lines that matched nothing are reported (ALLOW-UNUSED, INFO), so stale exemptions surface. Every exemption is listed in the report with the severity it removed, and the summary counts exempted blocking findings.
- The report's *Suggested allow-list lines* print ready-made lines for groups the reviewer ruled `false_positive` or `necessary` (with `human:<your-id>` when the review was not cross-family) — a person copies them; the executor never does.

`policy.json` holds venue and author policy; every key is optional, CLI flags win, and unknown keys are ignored and noted. A minimal example with illustrative values:

```json
{
  "venue": "ExampleConf 2099, double-blind",
  "page_limit": 9,
  "hardware": "block",
  "metadata_policy": "empty",
  "exempt_terms": ["HostNet"],
  "extra_deny": ["Falconwing"],
  "supp_max_mb": 100,
  "precision_disclosure": "exempt",
  "registration_labels": "keep"
}
```

| Key | Meaning |
|---|---|
| `venue` | free text shown to the reviewer |
| `anonymous` | `false` behaves like `— camera-ready` |
| `page_limit` | body must end on or before this page (PAGE-LIMIT) |
| `fill_page`, `fill_threshold` | body must end on this page and fill it to the threshold (PAGE-FILL, WARN) |
| `end_matter` | required closing statements in order: slots split by `;`, language variants by `\|` — or a list of lists |
| `hardware`, `framework` | confirmed level of a hardware or framework leak: `block`, `warn`, or `info` |
| `supp_hardware` | hardware, OS, and host words in the supplement's notes and names: candidates whose confirmed level is `hardware` (default), `warn` / `block` (another confirmed level), or `info` (reported, not reviewed) |
| `precision_disclosure` | numeric precision and weight-loading detail: `exempt` (default: never reported — a method parameter) or `candidate` (ENG-PRECISION in the paper, candidates in the supplement's notes) |
| `registration_labels` | preregistration amendment, addendum, and clarification labels: `keep` (default: a required disclosure, not reported; registration-record files INFO; a sentence of a registration-record member never goes as a whole; a reviewer finding is kept at INFO only when it holds nothing but a label the paper itself names or the order a registration states — a code name, a month-day date, a hardware word, a batch name, a correction, a re-run, or work completed later beside them keeps its level) or `flag` (PROC-REGLABEL and registration-record files become candidates; the fix keeps the timing fact and drops the label) |
| `skeleton_result_words` | extra words that state a result or a conclusion in your field (a list): a sentence or clause that holds one never goes as a pure-leak unit (`delete-sentence`), beside the built-in list (improve, outperform, show, find, significant, higher, lower, equals, reproduce, …) |
| `strict` | surviving WARN findings block |
| `metadata_policy` | `"empty"`: every non-empty PDF metadata field is at least WARN |
| `exempt_terms` | words that only look like a leak (a dataset named after a host); quiets candidates only, never a definite finding |
| `extra_deny` | internal code names that must not appear anywhere (ENG-DENY, redacted as `[DENY#n]`) |
| `supp_max_mb` | archive size limit |
| `declared_ai_uses` | what the AI-use statement declares, for the statements lens |
| `region_headings`, `body_end_markers` | override the section headings used for regions and the body end |
| `notes` | free text, ignored |

## Common false positives

| Word or pattern | Legitimate use | Handling |
|---|---|---|
| cluster, node, host, server, environment, kernel, container | statistics, graphs, RL, kernel methods | never a trigger alone; only operational phrasing becomes a candidate |
| agent, reviewer, the user, witness, lead | agent research, reviewer-model roles, chat roles, mathematics | not lexical triggers; PROC matches narrative phrasing only, then Tier B rules |
| model ids with versions (`Mistral-7B-v0.3`, `_v03`, `vicuna_v15`) | scientific content | ENG-VER is anchored to library names; in names, a lone `_v1` and a zero-padded `_v03` are not iteration marks, and a version right after a model family name (`vicuna_v15`, `llama_v2`) is the model's version |
| hardware in a latency or throughput paper; other people's hardware in related work | the claim depends on the platform | candidate → `necessary` or `false_positive`; HARDWARE sets the confirmed level; hardware that only gives a runtime context is `leak` |
| a run log or expected-output log in the supplement | the README uses it to check a reproduction | candidate → `necessary`; otherwise `leak`, and the fix leaves it out of the staged copy |
| "N cores" with no compute word nearby | game theory, chemistry | INFO |
| data-collection windows, knowledge cut-offs, benchmark versions | scientific information | candidate → `necessary`; a date range in a supplement note is not reported |
| dataset revisions, commit hashes, date-shaped seeds in the body | reproduction inputs | hashes are definite (move them to the supplementary README, or a human exempts them); a seed shaped like a date is a PROC-DATESEED candidate (describe the seeds in words; the values stay in code); never flagged in supplementary code |
| "see the supplementary README" in a reproducibility statement; "the README lists the commands" | a pointer the venue asks for | not reported next to "supplementary" or "appendix"; otherwise a README is INFO (still reviewed), and any file name is INFO in end-matter statements |
| bf16, fp8, int8 in a precision ablation | the claim depends on it | not reported by default; with `precision_disclosure: candidate`, rule `necessary` |
| "Amendment 11", "protocol addendum" in a public preregistration | the registration record | not reported with `registration_labels: keep` (the default) |
| `\n`, `**…**`, `\boxed{` or `??` inside a verbatim prompt table | intended verbatim text | INFO when the text around it matches a verbatim region of the sources; a `??` in reference context is never excused |
| attribute chains (`cfg.cluster.internal`), concatenated paths (`ROOT + '/data/x'`) | code | not hosts or paths; in code only a URL host, user@host, or a quoted hostname counts |
| shell prompts and hostnames inside model-generated records | data | WARN candidate in data files; BLOCK only with an identity term |
| SHA-256 in a security paper; prompt-injection research | the object of study | candidate |
| "a GPU with 24 GB", "tested on Linux" in a README | a reproduction requirement | a SUPP-HW candidate: rule `necessary` (or set policy `supp_hardware: info`) |
| `<DATA_DIR>/train.jsonl` in a README command; `${OUT}/x` in a shell script | usage notation | INFO in READMEs and comments; not reported in shell scripts and configs |
| `../outputs/run.json` written by the code | an output the code creates | a relative path that resolves to nothing is INFO, never reviewed |
| "the constant C is to be determined", "code will be released upon acceptance" | mathematics; a standard promise | PROC-PENDING candidate → `false_positive`; the release promise is not matched |
| a member named `NOTES.md` or `review.py`; `draft_model/`, `old_policy.py` | documentation; a module of the method; speculative-decoding drafts, RL policies | SUPP-PROCFILE reads weak markers (notes, status, review, round) only in documents and logs, and `draft` / `old` only at the end of a file name; a reviewer rules on the rest |
| `<answer>`, `<think>` tags inside prompts and model outputs; `vendor/x/y.py`; a dependency list | data; another package | not placeholder roots (only `/` after the tag counts); a script under a folder the package's layout does not have, on a line that calls it third-party or not included, in a DEPENDENCIES / LICENSE / NOTICE file, or inside a vendor, third-party, or shim folder is another package's — unless a command runs it |
