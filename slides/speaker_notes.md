# ARIS Framework & Design — Speaker Notes (3-slide version)

## Slide 1 — ARIS Design Philosophy
This slide introduces the single rule behind ARIS: a system can drive its own progress but can never acquit its own quality. DRIVE covers execution, scheduling, and mechanical checks and is safe for the same model. ACQUIT covers correctness, novelty, sufficiency, and completeness and must be handled by a different model family, which is why ARIS uses a cross-model jury of Claude executor and GPT-5.5 Codex reviewer plus deterministic verifier scripts. This rule then translates into Type-A and Type-B gates and into the independent effort and assurance axes. The bottom row shows how these ideas connect: no self-acquittal leads to a gate taxonomy, which leads to orthogonal controls and a shared six-state verdict vocabulary.

## Slide 2 — ARIS Framework & Detailed Flow
ARIS separates three roles. Claude executes, GPT-5.5 reviews, and deterministic scripts verify. All of them write to disk state, including receipts, REVIEW_STATE.json, and traces. These roles are arranged into six workflows: idea discovery, experiment bridge, auto-review, summary, paper writing, rebuttal, resubmit, and paper talk. Every skill integration follows a six-component contract and a helper resolution chain. On the right side are the cross-cutting mechanisms: reviewer prompts receive only file paths, round one uses a fresh Codex agent while later rounds continue the same thread, and the improvement loop uses a fresh thread every round as a bias guard. The fan-out pattern scales generation through parallel shards but keeps adjudication in a cross-model jury. Finally, no paper reaches submission until it passes five independent audit layers and the deterministic verify_paper_audits.sh gate exits zero.

## Slide 3 — ARIS Memory & Long-Cycle Operation
Long runs rely on disk as the source of truth. The memory layer uses research_wiki.py for persistent knowledge and per-workflow state files for recovery. The recovery layer uses run_state.py to separate done from accepted, resumes at the first non-terminal phase, and re-audits any done-but-unaccepted stage. The external cadence fence ensures that timers can only fire-control progress and never own verdicts, which is why verdict-bearing skills are never wrapped in /loop. The operation layer uses iteration_log.py and an overnight heartbeat to detect stalls, watchdog.py to monitor remote training, and Paseo orchestration to manage agent lifecycle. Review tracing writes four files per call and appends to events.jsonl. The bottom flow ties it together: memory enables recovery, recovery constrains operation, and operation produces an auditable trail.
